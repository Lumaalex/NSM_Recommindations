## 1. Что за проект

Детский центр, направление «Игровое взаимодействие» (ИВ). Конструктор рекомендаций для
специалистов: оценка ребёнка по сферам → подбор формулировок из банка фраз → готовый документ
(заключение/проект). Общение с заказчиком — **на русском языке**.

### Три клиента (две независимые ветки + Google) на общих данных:

| Клиент | Файл | Версия | Суть |
|---|---|---|---|
| **V1 «большая версия»** | `Конструктор_рекомендаций.html` | **1.3.0** | Классический поток: банк фраз, таблица, система оценок 3/2/1/0/N |
| **V2 «от общего к частному»** | `fork_v2/Конструктор_ИВ_версия2.html` | **2.6.0** | 9 шагов: сферы → FEDL2i → цели → приёмы → результаты → след. период → рекомендации → документ → **банк фраз** |
| **Google-версия** | `google/Index.html` (+ `Code.gs`) | 1.3.0 | V1-интерфейс + адаптер Apps Script (данные из листов таблицы) |

Мастер-данные: `tools/source_data.py` → `data/phrases.json` (версия данных **1.2.0**) →
`Банк_фраз.xlsx`; из них собираются все html-клиенты (`app/template.html`, `app/template_v2.html`,
общий `app/style.css`). Раздаточные копии — в `release/` (имена содержат форк и версию).

### Ключевые принципы (решения заказчика):
- **Форки независимы**: никаких перекрёстных ссылок V1↔V2 (запись 24 CHANGELOG).
- **Раздельные ключи localStorage**: `iv_constructor_doc_v1`, `iv_constructor_bank_v1` (V1);
  `iv_constructor_v2_doc`, `iv_constructor_bank_v2` (V2); общий только `iv_constructor_ui`.
- Каждое изменение = **запись в CHANGELOG.md** в формате: что изменено → **где реализовано**
  (файл, функция) → **что повторить в Google/мобильной версии**. README.md держать в синхроне.
- **Дисциплина заморозки**: пока заказчик тестирует один форк, не трогать общие данные и другой
  форк. Для частичной пересборки: `tools/build_v1_only.py` / `tools/build_v2_only.py`
  (полный `tools/build.py` перезаписывает xlsx/docx с новыми метками времени → md5-шум,
  содержимое идентично).
- Перед пакетом — md5-базлайн (`work/md5_*_before.txt`), после — `_after.txt` (доказательство,
  что данные/чужой форк не тронуты). Скриншоты каждого пакета — `work/shots/<префикс>_*.png`.
- **Скачивание**: браузер/вьювер скачивает тот файл, который СЕЙЧАС ОТКРЫТ → после сборки всегда
  делать `present_file` нужной копии из `release/`.

   использовать одинарные кавычки для литералов. Патч-скрипты — с assert'ами «ровно одно вхождение».
4. **md5-шум**: полный `build.py` перезаписывает xlsx/docx — метки времени внутри архива меняются,
   md5 отличается при идентичном содержимом. Для «замороженных» периодов — только `build_*_only.py`.
5. **Playwright не переживает сессию** (браузеры в `/tmp/.cache`) — в новом чате переустанавливать.
6. **Скачивание у заказчика**: скачивается открытый файл → всегда `present_file` той копии
   `release/`, которую нужно скачать; заголовок вкладки и имя файла содержат версию.
7. Рабочий каталог скриптов/артефактов — `/home/user/work/` (патчи `patch_*.py`, съёмка `shoot_*.py`,
